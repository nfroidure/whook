# @whook/otel
> OpenTelemetry instrumentation wrappers for Whook

[![GitHub license](https://img.shields.io/badge/license-MIT-blue.svg)](https://github.com/nfroidure/whook/blob/main/packages/whook-otel/LICENSE)


[//]: # (::contents:start)

This plugin instruments Whook-specific lifecycle steps with
[OpenTelemetry](https://opentelemetry.io/) spans and events.

## What is instrumented

- `httpRouter`: request-level router span with events for routing, parsing,
  execution and transfer completion timings.
- `httpTransaction`: child span for each transaction.
- `ROUTES_HANDLERS`: execution spans per route operation.
- `CRONS_HANDLERS`: execution spans per cron run.
- `CONSUMERS_HANDLERS`: execution spans per consumer run.

## Setup

Install the module:

```sh
npm i @whook/otel @opentelemetry/api
```

Register the plugin before `@whook/whook` so its wrapped services are picked
first:

```diff
$.register(
  constant('WHOOK_PLUGINS', [
    '__project__',
+   '@whook/otel',
    '@whook/whook',
  ]),
);
```

## About `apm`

The built-in `apm` service is still relevant as a lightweight structured logging
fallback. This plugin is opt-in and focused on OpenTelemetry traces, so it does
not remove or replace `apm`.
